# SunuPermis : Vercel, Neon et Gemini

## Préparation locale réalisée

Le projet exporte son API Express à travers un handler Vercel catch-all. En production, l’API exige `DATABASE_URL` et utilise PostgreSQL ; en développement local sans URL de base, elle conserve le repository JSON. Le handler refuse explicitement la requête si `DATABASE_URL` manque. Le schéma `server/data/schema.sql` ne s’exécute pas au démarrage; il a été appliqué directement dans l’éditeur SQL Neon pour éviter de lire ou d’utiliser le `.env` local.

La configuration Vercel inclut dans la fonction les fichiers lus dynamiquement (`js/data-*.js` et `server/data/raoul-knowledge.md`), et écarte les données locales du bundle. Le fichier `.vercelignore` exclut aussi les bases JSON et leurs sauvegardes, les fichiers d’environnement, les clés et les artefacts de développement de l’ensemble du déploiement, afin qu’ils ne soient pas servis comme fichiers statiques [7]. Aucune donnée locale de test n’a été importée. Aucune clé Gemini n’est stockée dans le code ou le `.env` local; `GEMINI_API_KEY` est déjà configurée comme **Secret** en Production sur Vercel, sans que sa valeur ait été lue. Le modèle par défaut est `gemini-3.8-flash` [5].

Pour la modifier, utiliser **Vercel → sunupermis → Settings → Environment Variables**, jamais Git, le code navigateur ou le chat. Confirmer dans l’interface sécurisée qu’elles visent Neon, puis les enregistrer comme **Secret**. L’API n’a pas été testée par une requête réelle; ne déployer qu’après validation et autorisation explicite. Ensuite, vérifier `/api/health`, `/api/questions` et `/api/raoul` [6].

Vercel exécute une application Express comme une fonction et ses fonctions ont un système de fichiers en lecture seule, hormis un espace temporaire non persistant ; c’est pourquoi le stockage JSON ne doit pas servir en production [1] [3]. Les fichiers utilisés par chemin calculé doivent être explicitement inclus dans `vercel.json` [2].

## Région choisie et plan Neon

Neon propose notamment Frankfurt (`aws-eu-central-1`) et London (`aws-eu-west-2`) en Europe. La région est fixée à la création d’un projet et ne peut pas être modifiée ensuite [8]. Vercel exécute par défaut ses Functions dans `iad1` (Washington, D.C.). Le plan Hobby permet de sélectionner une seule région; `lhr1` correspond à London et `fra1` à Frankfurt [10] [11]. L’utilisateur a confirmé London pour Neon (`aws-eu-west-2`) et l’API Vercel (`lhr1`); cette région est inscrite dans `vercel.json`. Le projet Neon est au forfait Free à London; son schéma a été appliqué le 27 novembre 2026 (résultat ci-dessous).

Le plan Neon Free coûte actuellement 0 $/mois. Il inclut notamment 100 CU-heures de calcul par projet et par mois, 1 Go de stockage Postgres par projet (20 Go cumulés par compte) et 5 Go de transfert réseau public par projet et par mois. En cas de dépassement, le calcul ou les écritures sont suspendus jusqu’au renouvellement du quota ou à une mise à niveau; le dépassement du plan gratuit ne déclenche pas à lui seul une facturation automatique [9]. Toute mise à niveau payante reste exclue sans nouvelle autorisation.

Lors de la vérification du dépôt public, `main` affichait le commit `c6a3dd9` et le README indiquait encore que les données sont stockées dans `server/data/db.json` [12].
